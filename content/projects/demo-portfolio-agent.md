这个项目是一个**个人作品集智能体**：招聘方打开作品集后，可以直接用自然语言询问候选人的经历、项目判断和人工智能产品能力。

# 用户问题

招聘方时间有限，不一定会把整个作品集读完。不同招聘方关心的问题也不同：有的人关心从 0 到 1，有的人关心人工智能，有的人关心商业结果。

# 核心洞察

[演示内容]

不同招聘方不会按同一顺序阅读作品集。因此，与其只做固定页面，不如让智能体按问题去检索证据。

这是产品假设，不是已经被验证的事实。

# 产品决策

第一版选择：

- 让大模型自主决定是否调用工具，而不是每个问题都走固定 RAG。
- 知识库与代码分离。
- 回答必须带来源。
- 资料不足时明确承认不知道。

# 备选方案

当时还可以选择：

1. 只做普通作品集网站。
2. 做站内关键词搜索。
3. 做固定流程的 RAG 问答。
4. 引入复杂多智能体框架。

# 产品取舍

第一版放弃了复杂框架、向量数据库、流式输出和长期记忆。原因是作品集体量很小，当前最需要验证的是：模型能否自主找证据，而不是把系统做得很像“人工智能”。

# 产品方案

用户在 `/agent` 提问。服务端运行智能体循环。模型可以调用 `search_knowledge`、`get_project`、`get_profile`、`list_projects`。知识库是本地 Markdown。

# 人工智能与技术设计

[演示内容]

- 为什么可能需要模型：招聘方的问题是开放的，固定搜索无法完成取舍、比较和“资料不足”的判断。
- 模型边界：不得编造经历；只能依据知识库。
- 评估方式：后续用 `evals/questions.json` 衡量事实正确率、幻觉率和引用正确率。
- [需要用户补充：延迟、成本、失败时的人工介入方案]

# 最小可行产品

第一版只做：

- 本地知识检索
- 四类核心工具
- 当前会话记忆
- 来源卡片

故意不做：登录、长期记忆、多智能体、复杂可视化。
